# Public discovery and official handoff

## What it is

Envoy offers one public search and detail API for jobs, support, funding, nearby services, and civic participation. Records retain their publisher, source URL, terms, evidence, freshness, and sample status. Signed-in residents can save a record and maintain their own checklist.

## How it works

`GET /api/v1/discovery` reads permitted `source_records`, joins their detail, listing, and area rows, and accepts `q`, `area`, `type`, `location`, `jurisdiction`, `audience`, `status`, `applicationStatus`, `source`, `language`, `freshness`, `limit`, `offset`, `includeSamples=true`, `includeFinders=true`, `includeClosed=true`, and `includeStale=true`. Areas are `jobs`, `support`, `funding`, `nearby`, and `participation`. The default excludes all fictional samples. A province code in `location` or `jurisdiction` also includes federal entry points. Free-text `location` searches place names, listing location text, and office addresses. `source` is an exact source registry ID. `GET /api/v1/discovery/:id` returns one item with full provenance and coordinates when available.

Jobs, Support, and Funding now default to individual source-backed records. A directory or finder appears only with `includeFinders=true`, allowing the client to request a separate fallback list with `type=jobs_finder`, `benefits_finder`, or `funding_finder`. Closed individual listings are excluded unless `includeClosed=true`; unverified or stale listings are excluded unless `includeStale=true` or a source-status/freshness filter explicitly asks for them. Pagination and `total` are calculated after these filters. A legitimately empty area stays empty rather than substituting a directory as if it were an opportunity.

Individual records have `type: job_posting | support_program | funding_opportunity` and a `listing` object containing `category`, `postedDate`, `closingDate`, `locationText`, and `applicationStatus`. Non-listing records return `listing: null`. `publisher` is the actual employer or program publisher; `sourceUrl` and `handoff.url` point directly to the official posting when a per-listing adapter provides one. Posted and closing dates are `YYYY-MM-DD` or null when absent. `applicationStatus` is `open`, `closed`, or `unknown`; expired source verification downgrades a stored open status to unknown, a past deadline is closed, and a deadline on the current date is unknown because the publisher's cutoff time may differ. `applicationStatus` filters that effective value. This status is distinct from `status`, which filters source freshness and verification.

`type` also distinguishes `jobs_finder`, `benefits_finder`, `funding_finder`, `service_location`, `consultation_finder`, `source_record`, and `sample_record`. `audience` is a **navigation intent**, not an eligibility decision: `job_seekers`, `benefit_seekers`, `funding_seekers`, `service_visitors`, or `civic_participants`. Responses carry `navigationAudience` and `audienceBasis: "navigation_only"`. `status` filters the source record state: `verified`, `current`, `stale`, `expired`, `error`, or `unknown`. `verified` uses the source's permitted-terms and freshness check; opening status belongs only to the listing metadata. The existing `freshness` filter remains an alias for the raw freshness state.

For example, `/api/v1/discovery?type=service_location&location=Victoria&source=service-bc-office-locations&status=verified` finds currently verified Service BC offices in Victoria. `/api/v1/discovery?area=participation&audience=civic_participants&source=federal-consultations-finder` returns the federal consultation finder link, rather than asserting a particular consultation is open.

`GET /api/v1/discovery/:id/handoff` returns an HTTPS publisher URL only for a permitted real record. It never records an external application or consultation submission. The client opens the publisher site, where the visitor confirms current deadlines, hours, eligibility, and completion. Finder links for federal jobs, benefits, funding, and consultations lead to the publisher's live search; they are not individual opportunities. Service BC records are actual locations, but visitors should confirm hours before travelling. Stale records remain visible with their freshness state.

`GET /api/v1/discovery/saved` lists up to 100 of the signed-in resident's saves. `PUT /api/v1/discovery/saved/:id` saves a record and optionally replaces a checklist; `DELETE` removes it. Checklist entries use `{ "id": "step-1", "text": "Review requirements", "done": false }`, with at most 12 short, user-authored entries. A checked entry is only the resident's own note. Saved items require the Applicant role and `write:profile` permission. Sample saves and reads require `includeSamples=true` on each request.

Migration `0013_discovery.sql` adds saved items and optional area tags. It seeds the [Government of Canada consultations finder](https://www.canada.ca/en/government/system/consultations/consultingcanadians.html) as a reviewed official link. Its short description is Envoy's own text; it does not claim any particular consultation is currently open. The link was reviewed on 2026-09-26 and expires after 14 days until refreshed. The page's [Canada.ca terms](https://www.canada.ca/en/transparency/terms.html) govern reuse; this feature stores link metadata rather than republishing the page.

## How to change it

Add new records through the source registry and a terms-reviewed adapter. An `OfficialIngestRecord` with `kind: null` and `listing` metadata is persisted to `source_record_listings`; its core source record carries the direct URL, publisher, stable external ID, payload hash, evidence URL, verification time, and expiry. The adapter must fail closed when a publisher page changes. Report a source ID in `refreshedSourceIds` only after a complete successful scan, including a confirmed zero-results state. The Worker then marks omitted prior listings stale; a failed source marks them error. New source IDs need `registry` metadata so the Worker can create the source before its records. `source_record_details.kind` still maps finder and location kinds to areas. The audience mapping follows the area as a browsing intent; add sourced eligibility fields separately if a real program adapter supplies them. Do not guess live deadlines, opening status, or availability from a finder. Keep the source URL, evidence URL, publisher, and freshness truthful. Add area-specific filters only when the imported record schema has reliable corresponding fields. The Worker route is `apps/worker/src/features/discovery/index.ts`; the root Worker dispatches to `handleDiscoveryRequest`. Resident and staff agent tools call the same route.

## Configuration

Apply D1 migrations through `0027_source_listings.sql` before ingesting individual listings; `0028` seeds separately reviewed program records. There are no new environment variables. API parameters are bounded to 100 results per page, a 120-character search, and 12 checklist entries. Account saves depend on the existing Auth0 Applicant role and `write:profile` scope. A browser client needs `GET`, `PUT`, and `DELETE` in the Worker's CORS methods.

## Dependencies

The feature uses `@civicresolve/db/d1`, `@civicresolve/sources`, the Worker Auth0 verifier, `@civicresolve/domain/permissions`, and Cloudflare D1. It consumes official source records imported by the source adapters, rather than scraping in a public request.
