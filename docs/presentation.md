# Four-minute Envoy live presentation

## What it is

This is the four-minute live Civic Technology judging run of Envoy, followed by three minutes of questions under the [Hack the Hill III rules](https://hack-the-hill-iii.devpost.com/rules). It follows one resident from an official source to a reviewable service report, then shows what the product can prove about that report. Keep the browser and a read-only Tiger query ready; show a staff action only after a real Auth0 role token has passed the deployed Worker. The separate Remotion review video is five minutes.

## How it works

Open with: “Envoy helps people find public services and opportunities, then turn a service problem into a trackable report. This is a practice civic workspace. No municipality or employer is participating, and a report here does not reach a government office.” Use real municipality names when describing locations.

### Rehearsal cues

Before starting the timer, load the combined public site, the BC source detail, a guest conversation, and the read-only Tiger query in separate tabs. Keep browser zoom high enough that the practice and source labels are legible. Hide the receipt token and any CLI credentials. Start the timer only after the combined Worker page and an API request have both loaded.

At 1:00, leave the source view even if the official publisher opens slowly; show the source URL and freshness already visible in envoy. At 1:50, use the typed feedback form if Workers AI is slow. At 2:40, show the dated private receipt only after masking its access token. At 3:20, return to the resident view unless a real Auth0 role action has passed. End at 4:00 on the public URL and the practice-workspace statement.

The Remotion review cut is timed to five minutes and now has short deployed-site recordings, dated Tiger query evidence, draft synthesized narration, and captions. It is an editing and rehearsal aid, not a completed live rehearsal or final submission video. A person still needs to run the entire four-minute live route against the final deployed build, time every transition, and mark which fallback was used.

ElevenLabs has a configured private intake agent and a seven-day, 5,000-credit-capped production API key expiring October 3. The Worker returned a signed URL, but no complete voice conversation and feedback submission has been accepted yet. Presage compiles in the native iOS app, but no physical-iPhone SDK reading has been accepted. Auth0's hosted sign-in is configured and visually checked, but a real staff token and role action have not passed the deployed Worker. Omit these provider demonstrations and prize selections until each acceptance is recorded. For the three-minute questions, keep answers concrete: sources show publisher, link, freshness, and sample state; external applications end at the official site; first-party submissions belong only to an actually participating organization; writes require a human review/approval; staff authorization is checked in the Worker; Tiger holds event metadata, not resident message bodies. State that the current organization and reports are practice data whenever that distinction matters.

## How to change it

Rehearse against the deployed build and replace each conditional step only after capturing its live success and any role denial. Update the evidence snapshot when a source refresh or analytics count changes. Use [the storyboard](video-storyboard.md) for footage and [the submission checklist](submission-checklist.md) for claims that must be gated before Devpost selection.

## Configuration

The combined public web and API origin is in [Deployment](deployment.md). ## Dependencies

This run depends on the combined Cloudflare Worker, D1, R2, Workers AI, official BC source links and data, and Tiger for the analytics segment. The optional employee segment depends on Auth0 live token acceptance and scoped organization membership. The optional voice and native accessibility segments depend on live ElevenLabs and Presage acceptance respectively.
