# Five-minute Envoy presentation

## What it is

This is the live Civic Technology judging run of Envoy. It follows one resident from an official source to a reviewable service report, then shows what the product can prove about that report. Keep the browser and a read-only Tiger query ready; show a staff action only after a real Auth0 role token has passed the deployed Worker.

## How it works

Open with: “Envoy helps people find public services and opportunities, then turn a service problem into a trackable report. This is a practice civic workspace. No municipality or employer is participating, and a report here does not reach a government office.” Use real municipality names when describing locations.

The current production evidence snapshot on 2026-09-26 is: Pages returned HTTP 200; the public Worker source endpoint returned 69 records, including 65 Service BC offices and three current BC finder links. The federal consultation finder was stale and unverified. A production Toronto streetlight prompt returned a reviewable Workers AI proposal, which was acknowledged and submitted as a practice report. A read-only Tiger query at 19:41 UTC returned four delivered `feedback_events` and four aggregate events, including the new report's `feedback.submitted` and `feedback.classified` sample events. These counts are a snapshot, not a promise about the live presentation. Recheck immediately before presenting.

ElevenLabs has a configured private intake agent and a seven-day, 5,000-credit-capped production API key expiring October 3, but its signed-URL request currently returns HTTP 401; no live voice submission is accepted yet. Presage compiles in the native iOS app, but no physical-iPhone SDK reading has been accepted. Auth0's hosted sign-in is configured and visually checked, but a real staff token and role action have not passed the deployed Worker. Omit these provider demonstrations and prize selections until each acceptance is recorded. The native app has a generic-device build; do not claim its recorded flows have run on a device against production until they have.

For the three-minute questions, keep answers concrete: sources show publisher, link, freshness, and sample state; external applications end at the official site; first-party submissions belong only to an actually participating organization; writes require a human review/approval; staff authorization is checked in the Worker; Tiger holds event metadata, not resident message bodies. State that the current organization and reports are practice data whenever that distinction matters.

## How to change it

Rehearse against the deployed build and replace each conditional step only after capturing its live success and any role denial. Update the evidence snapshot when a source refresh or analytics count changes. Use [the storyboard](video-storyboard.md) for footage and [the submission checklist](submission-checklist.md) for claims that must be gated before Devpost selection.

## Configuration

The public web origin and API base are in [Deployment](deployment.md). Use the production Worker and current Pages build, English locale for the judging path, a non-emergency practice report, and a read-only Tiger session. Keep guest receipt tokens, Auth0 tokens, API keys, and résumés off screen. Do not enable paid provider plans or overages for a demonstration.

## Dependencies

This run depends on Cloudflare Pages, Worker, D1, R2, Workers AI, official BC source links and data, and Tiger for the analytics segment. The optional employee segment depends on Auth0 live token acceptance and scoped organization membership. The optional voice and native accessibility segments depend on live ElevenLabs and Presage acceptance respectively.
