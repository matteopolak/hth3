# Four-minute Envoy live presentation

## What it is

This is the four-minute live Civic Technology judging run of Envoy, followed by three minutes of questions under the [Hack the Hill III rules](https://hack-the-hill-iii.devpost.com/rules). It follows one resident from a source-linked job and nearby service to a reviewable service report, then shows what the product can prove about that report. Keep the browser and a read-only Tiger query ready; show a staff action only after a real Auth0 role token has passed the deployed Worker. The submitted video is five minutes and does not replace this live run.

## How it works

Open with: “Envoy helps people find public services and opportunities, then turn a service problem into a trackable report. Reports currently go to the Envoy review team. No municipality or employer participates yet, and reports do not reach a government office.” Use real municipality names when describing locations.

### Rehearsal cues

Before starting the timer, load the combined public site, a source-linked job, the Nearby map, a guest conversation, and the read-only Tiger query in separate tabs. Keep browser zoom high enough that destinations, source links, and approval controls are legible. Hide the receipt token and any CLI credentials. Start the timer only after the combined Worker page and an API request have both loaded.

At 1:00, leave the source view even if the official publisher opens slowly; show the source URL and freshness already visible in envoy. At 1:50, use the typed feedback form if Workers AI is slow. At 2:40, show the dated private receipt only after masking its access token. At 3:20, return to the resident view unless a real Auth0 role action has passed. End at 4:00 on the public URL and the Envoy review-team destination.

## Configuration

The combined public web and API origin is in [Deployment](deployment.md). Use the production Worker, English locale for the judging path, a non-emergency report directed to the Envoy review team, and a read-only Tiger session. Keep guest receipt tokens, Auth0 tokens, API keys, and résumés off screen. Do not enable paid provider plans or overages for the presentation.

## Dependencies

This run depends on the combined Cloudflare Worker, D1, R2, Workers AI, official BC source links and data, and Tiger for the analytics segment. The optional employee segment depends on Auth0 live token acceptance and scoped organization membership. The optional voice and native accessibility segments depend on live ElevenLabs and Presage acceptance respectively.
